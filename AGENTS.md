# ForgeUI project context

## Project

ForgeUI is a native Godot 4.7.2 Commander frontend using the real Forge engine for card rules, costs, legality, targeting, combat and decisions. The application supports a table of up to four: one local human plus bots and, online, friends running this same build. Its home is a procedural retro computer with a live CRT screen and floppy deck carousel; the editor, settings and battlefield are Godot Controls. Online play is host-authoritative and does not use Forge's netplay protocol, so stock Forge cannot join; see `docs/online-play.md`.

## Stack & architecture

- Godot uses GL Compatibility; do not depend on Forward+-only lighting effects.
- Entry: `client-godot/scenes/Application.tscn` → `scripts/app/Application.gd`; battlefield: `scenes/Main.tscn` → `scripts/ui/Main.gd`.
- Java 17 bridge lives in `bridge/src/main/java/forgeui/bridge/`. `LibraryMain` normally serves deck/application requests on local port 7778.
- `MatchService` owns a separate `BridgeMain` JVM per active match, using a dynamic local port. Only stop processes owned by this application/test.
- Online: `OnlineLobby` (in `LibraryMain`) holds the online port until PLAY, then hands it and the joined players to `BridgeMain`, which keeps one `Seat` (own `BridgeGuiGame`/controller/snapshots) per human. Only `BridgeServer.exposed` listens beyond loopback, and it never exposes the library or host seat. Empty seats are open automatically; there is no "open" slot type to set.
- `LibraryClient.gd` handles library request/response JSON over WebSocket; `LiveAdapter.gd` handles the game protocol and normalized snapshots. `MockAdapter.gd` is a test/demo substitute, not rules authority.
- Game protocol v2 mutations require session/revision/request identity. Reconcile cards by instance ID, replace the outstanding asks set, preserve hidden-card permissions and never replay stale actions.
- A won game shows the full-screen YOU WIN outcome screen (`ui/OutcomeScreen.gd`: ASCII rain, falling block letters, one I WON button), then runs the same zoom-out and FORMAT A: wipe without a confirmation. Losing shows the same screen as YOU LOSE once; its I lost button closes it and the player keeps spectating, with End game still in the rail. Right-clicking one of your declared attackers during Declare attackers calls it back (bridge `undeclare`, a right-click on Forge's InputAttack). Face-down permanents show the standard Magic back and their public 2/2; chosen colors (`chosenColors`) show as mana symbols on the card. Returning home parks the same match; its session disk resumes it. Confirmed End Game stops the owned engine independently of presentation, returns home if needed, then silently plays FORMAT A: on the CRT with amber drive activity. No floppy moves: the session disk fades and is consumed, and the deck's disk reappears in the carousel without an ejection. Saved decks are never formatted.
- `forge/` is vendored upstream source/assets pinned by `FORGE_COMMIT`; prefer frontend/bridge changes over editing upstream. It carries local, uncommitted netplay stability patches recorded in `FORGE_PATCHES.md` (patch: `forge-patches/netplay-fixes.patch`); keep them, record any new upstream edit there, and re-apply them when updating Forge.

- Bridge `BridgeGuiGame.java`, `GameStateJson.java`, `BridgeProtocol.java`, `StackInteractionPolicy.java` — GUI callbacks, visibility-filtered state, request validation and response policy.

- `app/ScaledSurface.gd` — native-resolution editor/game/settings viewport at the device's selected UI scale, with engine-managed input mapping. `app/DisplayPreferences.gd` persists the local scale in `user://display.cfg`, separately from match/lobby configuration: Automatic defaults to 100% on Windows and 200% on Mac; Settings offers 100–200% in 25% steps. Apply after Save & Return. Editor input passes through above its workspace except during dialogs; raise its outer surface above the carousel for popups, then restore it. Internal z-order cannot escape the viewport texture. Keep the same game surface across reveal/park/resume/cleanup; confirmations use the same device scale.

- `ui/LayoutLoopGuard.gd` — watches every table ScrollContainer, including dynamically added dialogs. After 64 sorts of one scroller in a frame, suspend automatic scroll-content sizing and presentation, preserve the same polling adapter/latest snapshot, and show Retry display / Return to main menu. Retry restores original sizing/visibility/process modes and presents the newest snapshot. Do not solve UI queue exhaustion by increasing its memory limit.

- `app/ClientDiagnostics.gd` — optional bounded local state/layout capture for diagnostic packages; normal source defaults off.

## Design rules
- **Tether** (the user's name for it): a decision shown as a small terminal box tied to its card by a leader line, with the card outlined, instead of a popup. Use a tether for any decision about one visible card: yes/no confirmations, card modes, ability and mana choices (Canopy Vista: one click adds that color, [N] Cancel), all in `CardCallout.gd` placed by `InteractionPanel`; when the card is not on the table, fall back to the popup. `ResponseTarget.gd` is the tether for answering a stack spell with one you are casting.

- Preserve gray matte plastic hardware, colorful floppies, teal CRT terminals, purple UI accents and digital HP. Physical PLAY/SETTINGS glyphs are charcoal, not purple/glowing; keys match case plastic.
- Keys must visibly spring back and render raised before setup or camera/disk movement. Keep existing press consumption/cancel semantics.
- Keep the continuous drive slot fitted to the inserted disk with equal side clearance and centered between SETTINGS and the flat fascia's right edge. Its feed axis moves with the slot; height, throat depth and width stay fixed. Align the pinhole/activity dot with the slot centerline in the right margin. Disks finish rotating clear of the fascia before feeding straight; the recessed flap clears the shared disk representation for PLAY, resume, FORMAT and ejection. The former right-hand eject cap and pocket are removed.
- Dark home is the same room at night: real teal CRT spill, subtle cool rim and quiet background. Drive effects from the existing darkness tween; preserve original daylight rendering and zero night-light energy at daylight.
- Carousel faces are 2D cached textures. Night shading must remain presentation-only; never alter raw faces, sampled shell colors or insertion textures. Avoid per-frame face repainting.
- Home speckles scroll out/fade with the room; editor stays clear. Home carousel loops; editor is finite with a final blank + floppy. Keep shared disk continuity and cold-load responsiveness.
- Monitor shows the selected disk plus a FIND> search bar (home typing, Backspace, Escape clears; click focuses) that narrows the carousel by deck/commander name; disks still select decks. Search clears on entering the editor and is never persisted. Keep text inside rounded glass safe bounds. Preserve CRT effects and their fullscreen fade; settings uses fixed-size depth-tested glass.
- Boot starts at drive contact, with real deck/player data and readiness gates. No intermediate inserting screen, timer-only completion or hidden required-prompt deadlock.
- Artwork warms in the background from Play onward. The child's combined printing manifest includes every actual deck, including generated bots, without shuffled order or hidden-zone assignments. Match creation never waits for artwork or an image acknowledgment. Prioritize public/visible cards, commanders and cheap early plays; keep lookup/download/decode work bounded, share the gameplay cache, and retry failures quietly. A cached printing of the same card/face can appear while its exact printing warms; never substitute a front for a back or disclose hidden faces.
- Use Forge's avatar atlas, not AI-generated preset portraits. HP segments are teal; active-turn light is purple. Starting-player chooser shows portrait/name without HP.
- Every seat sees the same Forge starting-toss result and knows who is choosing the starting player. Show a coin for two players, a three-sided prism die for three, and a four-sided tetrahedral die for four; dice use player initials (number repeated initials) in stable engine-ID order. Play the short animation on the visible table, preserve the winner's real choice, and keep nonwinning seats informed without confirmation clicks. Snapshot updates must not replay it; completed sessions cancel it and later-turn reconnects skip it.
- Do not render the battlefield hand before Forge accepts Keep and required bottom-card choices. Each zone menu expands from its icon on its owner's board.
- Online table loading uses shared `tableReady`, so one seat's opening acknowledgment never gates another device. Human Keep/Mulligan inputs appear together; each seat's `openingHandComplete` closes its opening overlay after its real Keep/bottom decisions, without waiting for that seat's first turn. Host stop sends a terminal `sessionEnded` before socket teardown; joined apps clear credentials and return home automatically, including parked/loading sessions. Brief disconnects retry; an unavailable host times out after 180 seconds.
- Joining clients persist reconnect credentials and public session-disk metadata in `user://online-session.cfg`. A restarted app offers a Rejoin online game disk and reconnects to the same host-held seat/match from a fresh snapshot, never replaying pending actions or storing hands. Host recovery is unsupported; the host must remain running and holds absent seats for five minutes. Leave, confirmed in-game Quit, completion, host end and failed reconnect clear persisted credentials. Forget session clears an unconnected disk locally.
- Table settings (top of the rail) slides the hand, library and your health/portrait panel (kept on the table, above the library), sets how much of each shows, hand spread/visible count/angle, pile spacing and whether tapped pile cards turn aside, a per-seat Stack responses level (Everything / Smart default / Only threats; see the stack rule below), hand-card toggles for a mana-cost overlay (gray numbered generic pip, then one pip per colored symbol; default off) and Highlight playable (purple glow from Forge's priority-time actionable scan on your hand, commander and graveyard/exile casts, plus a purple rim on zone icons holding one; default on), a built-in library back (Forge sleeve atlas) and an optional stack notification sound (synthesized Chime/Bell/Pop, or an MP3 dropped onto the window, copied to `user://notification.mp3`). `Main.gd` saves it to `user://table-layout.cfg` for every game and clamps the hand and library to the table.
- Keep the left mana/phase groups aligned with breathing room. Required rail controls belong in shared scrolling layout, never overlapping headers/buttons.
- Stack items auto-pass when the seat has no legal response, except an opposing board wipe that reaches this seat's permanents: it always waits, so the seat sees it before anything leaves. That wipe shows as its card large in the middle of the table with branches to every permanent it reaches (all players', the bridge's `affected` ids; yours brighter) and a terminal bar with Respond with action (keep priority, act on the table) / I accept (pass) (`IncomingEffect` wipe mode), not the large popup. Targeting a stack item with a spell you are casting (Counterspell -> Wrath of God) is `ui/ResponseTarget.gd`: the cast spell large mid-table, a terminal menu branching off it with the target large, a branch from that card to its stack entry, and [Y] Card A -> Card B / [N] Cancel; the bridge marks such asks `casting` and names the spell as `sourceCard`. The host bridge's Smart policy (`StackInteractionPolicy`) otherwise holds a seat for another player's instants/sorceries, board wipes, effects targeting or touching that seat's things, unknown effects, and anything the seat can counter/Stifle. Abilities and triggers that only touch their controller's own things pass, including targets the controller chose among their own things and references such as TriggeredAttacker/Enchanted/Remembered that Forge resolves to their own cards (Stinkdrinker Bandit). Untargeted draw/life/mill/scry effects on other players ("each opponent loses 1 life", "each player draws") pass with a small non-blocking card popup for affected seats; discard, sacrifice and damage keep the window. Each seat's Table settings level applies on top: Everything waits on any opponent item it can answer; Only threats passes everything except respondable effects aimed at its things and board wipes (with the popup), and an opposing targeted effect or wipe it cannot answer still shows a small card popup. The large effect popup appears only while an item waits on this seat; anything informational (already resolved, auto-passing, untargeted notices, or a large popup whose item resolved) is a small card centered on the table: source card (the real public card for delayed triggers), arrow to the affected cards, short text and OK. Board-wide removal is announced only to seats it can reach (a delayed sacrifice of someone else's token is not). It never times out and OK only clears it locally, never an engine answer. Preserve required payment/target/selection decisions; never bypass Forge resolution.
- In solo bot games, checked phase stops pause on every player's turn even without a legal response; defaults are M1, DA, DB and M2. Phase buttons show configured stops, never transient action availability.
- Bind online prompt buttons and selections to the seat's current Forge input; input removal/replacement invalidates them immediately. Online default empty-stack priority after attacker/blocker declarations auto-passes without a legal action; explicit stops still pause, and declaration inputs always remain required.
- After PLAY in an online lobby the CRT dashboard becomes a ready screen (`DeckConsole._draw_ready`, data from `OnlineSession.party`): a READY banner, N/M humans ready, who is still awaited, and each seat (host/net/bot/open) with its state. Bots show AUTO and never count.
- Each online human presses their own PLAY key to ready up; the host launches only when all seated humans are ready. Deck, host configuration and roster changes invalidate readiness. Bots and empty seats need no confirmation. Default empty-stack phase stops belong to the active player; on another player's (or bot's) turn a seat auto-passes empty-stack priority even when it holds an instant, and its phase buttons for that player show unchecked unless explicitly checked. Stack responses, required declarations and explicit phase stops remain available.
- Decisions that pick from the board (targets, card selection, mana payment, attackers, blockers) sit in the right rail, never over the board; the stack stays visible beside them when it holds anything. The stack glows whenever it waits on this seat (decisions and resolve/respond windows, not automatic passes). View battlefield shows a large, see-through, pulsing Return to decision button centered over the table (solid on hover; Escape also returns). Damage assignment shows one column per recipient: big amount, (Lethal) once it kills, −/+, card below.
- Keys: Space passes the turn (Forge end-of-turn yield via bridge `pass_turn`; stops when attacked, targeted or facing mass removal), Q presses the primary button, D takes a pending draw.
- Card searches and other Forge card/player/stack picks (`SelectionPanel`) use a terminal window: a command-line header, a list that stacks identical cards (FOREST ×3; each click still sends one exact instance, the next unpicked copy), the source card under the list and a large card-shaped preview of the highlighted row, with ↑↓/Enter. Library searches (offered cards in no visible zone) replace the list and preview with a carousel (`ui/CardCarousel.gd`) of the same stacked groups: moving like the home floppy carousel (one continuous closeness curve, eased fractional cursor, drag/wheel/←→): the focused card large in the middle, neighbors smaller, darker and behind. Clicking a side card turns to it; left-clicking the middle card (or Enter) only adds a mark locally, right-click (or Backspace/Delete) removes one; nothing reaches Forge until OK, which sends each marked instance in turn and then answers.
- Show source-card context for decisions; preserve optional no-target choices, image aspect ratios/rounded corners and continuous scrollable rules.
- Clicking an ability in a "Choose ability"/mana popup activates it immediately (same engine answer as Confirm); card modes and multi-select choices keep select-then-Confirm.
- Card popups show large card faces without repeating their printed rules alongside them. Keep actual decision instructions and ability-specific context readable.
- Matching opponent battlefield permanents can group with a quantity badge, preserving each instance ID. On the human board, grouping requires the explicit Clean up board action (it only stacks identical permanents and moves nothing else) or dropping a permanent onto an identical one; new plays and manual placements never auto-join a previous pile. Stack/Tax badges are white tiles with black text drawn at native resolution. Tapping turns a card and offsets it slightly downward inside its pile so the card behind stays clickable, without moving the pile anchor or its neighbors; other different visible game states, combatants and attachment hosts stay separate.
- Right-dragging or Shift + left-dragging an untapped pile moves all of it (a plain right-click still inspects); a pile formed by dropping or Clean up board stays at its target card's spot; it keeps that spot through tapping until Clean up board. Hand cards never group or show quantity badges. Dragging one battlefield card out of a pile splits that instance, immediately recalculates both counts and preserves the manual separation across snapshots; zone changes clear the split.
- Dropping battlefield equipment on a controlled creature requests Forge's legal equip ability and that target. Spend floating mana first; incomplete payments offer battlefield sources and Cancel. Preserve real response windows and engine resolution.
- Forge's bundled Commander precons are listed as read-only `precon:` decks after saved decks; edits save as a new custom copy, never overwrite or delete them. The ALL/CUSTOM/PRECONS header filter is shared by home and editor. Carousel floppies build faces lazily when first visible.
- Artwork changes retain editor scroll. Validation is inline; cached image requests need stale-response guards. Saved decks preserve exact quantities/printings and accented names.

- Use one shared UI with device-local adjustable scale, never an unconditional 2× layout or separate platform UIs. At 100%, retain the original Windows header/carousel proportions; larger scales enlarge the same controls and logical viewports. Preserve the physical computer/CRT size and Play/Settings access. Use each surface's `ui_scale` for coordinates, workspace offsets and whole-pixel viewport expectations. Physical keys follow the shelf in sibling order; settings retains its visible roster and scrolling page. Scale changes must not alter online configuration/readiness or restart a parked engine.

- Hidden scaled UI surfaces suspend rendering; keep their source texture rendering explicitly enabled while the CRT zoom borrows it. Visible animations retain full-resolution continuous rendering. Hand/hover mirroring runs once before drawing; lifted hand cards share the original cached face texture instead of painting a second hidden viewport. Stationary combat arrows retain their geometry until endpoints change.

- Open card context menus on right-button release, so the menu cannot steal the release and leave the card holding mouse capture. Editor dialogs and embedded popup menus must own the full scaled input surface; background deck cards cannot open details while a popup is active.

- macOS build: `python3 client-godot/tools/package-macos.py` creates a universal DMG with separate Temurin 17 arm64/x86_64 runtimes. See `docs/macos-build.md`. On macOS, `BundledService` resolves payloads under `Contents/Resources`, selects Java by executable architecture and uses `:` in the classpath. Builds are ad-hoc signed unless Developer ID signing/notarization is added separately.

## Working rules

- Windows and Mac share https://github.com/LandonPatam/ForgeRevamp and one `main` branch; use short-lived feature/fix branches, not permanent platform branches. See `docs/development-workflow.md`. Reconciliation and platform checks are recorded in `docs/mac-reconciliation.md` and `docs/windows-reconciliation.md`; keep the old Mac checkout/backup. For this initial consolidation the user explicitly deferred live cross-platform play until after merging; that testing and an additional reported in-game online issue remain pending, not fixed or verified by the local suites.
- At task start inspect Git status, branch and commit. Coordinate one writer at a time on a shared feature branch; use separate branches for concurrent tasks. Handoffs reference a pushed branch/commit, checks and remaining issues instead of asking another agent to recreate code. Commit/push when authorized by the task; do not auto-switch dirty worktrees or force-push shared history.
- The agreed default for requested game updates is: implement and run relevant checks on Windows in a short-lived branch, commit/push that branch, then provide the Mac agent with its exact branch/commit and a concise rebuild/test prompt. This workflow authorizes those feature-branch commits/pushes unless the user requests local-only work. Mac pulls the same implementation, rebuilds affected components and tests; it pushes compatibility fixes to the same branch during its coordinated turn. Windows pulls those fixes and rechecks affected behavior. Merge into `main` only after both platforms have passed the affected checks on the final code; otherwise report Mac validation pending. Documentation-only changes need diff/link review, not game builds on both platforms.
- Finish initial Mac reconciliation before new online feature work. Online changes require relevant bridge/client checks plus Windows-host/Mac-join and Mac-host/Windows-join testing when hosting or shared protocol behavior is affected. Keep session/revision/hidden-information guarantees. Preserve both platforms' launchers, packaging and export presets. Windows `.exe` and Mac `.app` releases are separate builds from the same tagged source commit; release publication is a separate task.
- Don't scan the whole codebase. Start from this map and open only task-relevant files; ask if unsure where something lives.
- Ask before large refactors or renaming files. Keep diffs focused on the request.
- Preserve existing modified/untracked work. Do not reset/clean the tree or delete user decks/caches as a routine fix.
- Fix-and-test pipeline (details in `docs/testing.md`):
  0. Keep testing proportional: UI-only changes get one matching `ui`/`visual` check and the user's own play, no new scenario. If a check fails but the feature looks right, stop and ask the user instead of rewriting working code; never raise timeouts to pass a flaky check. Tests assert observable behavior, not exact wording, node names or pixel sizes.
  1. Reproduce a reported gameplay (engine/rules) bug first with a real-engine scenario: `tests/scenarios/<name>.state` plus a `<name>()` driver in `tests/ScenarioIntegration.gd`. Confirm it fails.
  2. Fix the bug.
  3. Run only the checks for what you touched, via `node client-godot/tools/check.mjs ui <Name>` / `scenario <name>` / `bridge` / `online`. The runner is quiet; full logs are in `client-godot/artifacts/check-logs/`.
  4. Inspect captures only for visual changes (`visual <Name>`).
  5. Run `check.mjs all` once before a push, not after every edit. Java checks are unnecessary for frontend-only changes.
- UI sandbox: `node client-godot/tools/sandbox.mjs <board>` opens the real table on a prepared board (`tests/sandbox/` playgrounds or any `tests/scenarios/` board) past startup, and relaunches the window on the same live board when sources change; `--mock` for the mock table, `--shot` for a screenshot. Details in `docs/testing.md`.
- Presenting a UI/table change to the user always goes through the sandbox, so they never have to play a game to reach it:
  1. Pick a board that shows the change at once (`sandbox.mjs` with no arguments lists them). If none does, add one: a playground under `tests/sandbox/`, or, when the change also needs an automated real-engine check, `tests/scenarios/<name>.state` plus its driver (the sandbox opens those too). Start the file with a `#` line saying what to do on it.
  2. Check it yourself before handing over: `sandbox.mjs <board> --shot` (or `scenario <name> --render`) and look at the PNG.
  3. In the reply, give the exact command and the short steps to reach the change on that board (e.g. "tap a Mountain, cast Faithless Looting"), then what they should see. Mention that saving a script relaunches the open window on the same board, so they can ask for tweaks while it stays open.
  This applies to home/editor changes only where a board makes sense; otherwise give the closest launch command (`run.sh`, `--mock`).
- Bash launch on Windows: `bash ./client-godot/tools/run.sh`; add `-Decks` or `-Mock` as needed.
- App/home UI checks (not in the runner yet): `node client-godot/tools/app-check.mjs --render` (or `--editor-preview`), `node client-godot/tools/library-check.mjs --render`, and `.\client-godot\tools\run.ps1 -Capture`.
- Automated playtest as the human seat across precons: `node bridge/tools/playtest.mjs` (see `docs/playtest.md`).
- Online checks: `node bridge/tools/online-check.mjs` (real lobby, seats and hidden information; contacts no router).
- Run suites that host online lobbies serially: they share Forge's configured online port. On Windows, test helpers must resolve `java.home` and launch its actual JVM; killing a PATH launcher shim can orphan its JVM and keep inherited output pipes open.
- Windows build: `.\client-godot\tools\package.ps1` (add `-SkipBuild` if the bridge is already built) writes `dist/ForgeUI/` and `dist/ForgeUI-windows.zip`; needs the Godot 4.7.2 export templates (`client-godot/export_presets.cfg`) and JDK 17. It bundles a jlink runtime and Forge `res/` without `adventure/`. Installed builds keep logs/startup status in Godot's `user://service`. Keep `tests/` in the export (`Main.gd` preloads it) and list non-resource files such as JSON in the preset's include filter. ## Release packaging

When asked to package a build for release:

- Build only with the packagers (`package.ps1` on Windows, `package-macos.py` on Mac) from a clean, committed `main`. The release is exactly their output: `dist/ForgeUI/` + `dist/ForgeUI-windows.zip`, or the Mac DMG. Never zip the repo or any folder by hand.
- Ignore everything else. None of it belongs in a release, and none of it should be copied, zipped or uploaded: `client-godot/artifacts/` (test captures and logs), `artifacts/`, `backups/`, root `ForgeUI-*.zip` handoffs, other `dist/` folders and zips (old builds, `*-mac-transfer-*`), `*.log`, `.tools/`, `.godot/`, `bridge/target/` (the packager copies what it needs), `docs/`, `tests/scenarios/` and user decks or caches.
- `client-godot/assets/cards/` are test fixtures, excluded from exports in `export_presets.cfg`; keep them out. The game downloads card art at runtime. A Windows game pack well over ~10 MB means something unintended got exported, so check the export filters.
- Don't delete or tidy the ignored folders while packaging; only the user decides that. Publishing a release (tags, GitHub releases, uploads) is a separate task that needs the user's go-ahead.
